# Reconstructing DIVER: A Personal Account
### *From a Paper Listing to a Working Program*
**Author: John Dunlop, 2026**

---

## 1. The Paper Source and the Fraction Puzzle
The reconstruction project began with an unreferenced, stapled printout of a BASIC computer listing from the winter of 1978/79. Initial attempts to convert the document using optical character recognition (OCR) failed significantly due to severe typesetting anomalies. Crucially, the OCR consistently substituted the fractions `¼` and `½` into conditional blocks.

Resolving this logic puzzle required parsing the source code line-by-line alongside close examinations of the original physical sheets. Line 1800 proved to be the structural Rosetta Stone:
```basic
1800 IF AL(AL,1) <> 5 THEN 1881
```
By analyzing the paired comparison operator context, it became clear that the print head or terminal configuration had mapped `¼` to represent `<` (less than) and `½` to represent `>` (greater than). Re-applying this translation across the entire listing resolved the broken conditional statements, restoring a coherent control-flow path.

## 2. Hardware Forensics: Identifying the Host Machine
Isolating the original target machine was a lengthy diagnostic process. While early analysis suggested BBC BASIC due to its native `PLOT` statement syntax, the chronology was incorrect - DIVER pre-dated the launch of the BBC Micro by several years. Furthermore, standard PDP-11 systems of that era failed to explain the cryptic string arguments trailing the graphics commands.

The breakthrough occurred after cross-referencing surviving Royal College of Art (RCA) press items and Department of Design Research documents. Archival material confirmed the department had acquired a Compucolor II desktop computer in 1978. A review of the Compucolor terminal-control manual revealed an identical syntax to the obscure `PLOT` expressions found in the listing.

A physical discrepancy remained: the Compucolor II features a small, integrated display outputting a 64×32 character grid, whereas DIVER's code clearly addressed an 80×48 canvas. This indicated that the software was developed within the broader Intelligent Systems Corporation (ISC) Intecolor 8000 professional terminal family, which shared the same core firmware but supported larger professional CRT monitors.

## 3. Emulation Experiments and Digital Archeology
Using Jim Battle’s browser-based Compucolor II Emulator (`CCEMU`), I gained an environment capable of executing isolated snippets of the original BASIC. While restricted by the emulator's smaller grid limits, running target subroutines allowed us to reverse-engineer how specific ISC control codes and memory operations actually manipulated screen buffers.

An exhaustive audit of the `PLOT` syntax alongside the scanned Compucolor 8001 engineering manuals corrected long-held misconceptions. For example, a command at line `[1261]` had originally been commented as an extended character set initializer; parsing it through the manual proved that Code 2 entered Graphic Plot Mode, meaning the numbers `14,15` were literal X/Y raster coordinates rather than independent commands. Similarly, plot submode `246` was discovered to be a hardware-driven `Y Bar Graph` tool rather than an X-axis renderer.

## 4. Re-engineering Philosophy: Mitigating AI Bias
Because I chose to rewrite the system into a modern, browser-accessible React/JSX application, I leveraged AI assistants to translate the historical logic. This introduced a unique preservation challenge: modern LLMs possess deep, inherent stylistic preferences for contemporary design conventions.

The AI repeatedly attempted to "correct" or "clean up" the system's output - substituting smooth vector paths, standard modern error strings, and clean diagonal graphs in place of the original rendering behaviors. For example, the non-WORK dive profile renderer had initially been built as a single-point-per-tick calculation approximation. However, deep mathematical analysis of the BASIC showed it issued specific vector lines from coordinate `(LP,MP)` to `(LQ,MQ)` on every tick. 

To achieve true historical fidelity, the entire rendering module was re-architected. The resulting JSX version deliberately bypasses smooth browser paths, meticulously drawing the exact jagged vertical and horizontal raster fragments generated by the old Intel 8080 CPU.

## 5. Architectural Style Rules
To safeguard the historical validity of the codebase, a strict project style guide was enforced:
1. **Absolute Accounting:** Every single line of the original 575-line BASIC printout must be explicitly accounted for, including raw remarks and non-executable headings.
2. **Variable Namespace Separation:** All variables derived directly from the historical listing are prefixed with `BASIC_` (e.g., `BASIC_AL`, `BASIC_DT`), allowing researchers to easily isolate modern structural hooks from original 1978 logic.
3. **No Retroactive Upgrades:** Any known abnormal termination path or unhandled boundary lockup (such as freezing without a message when exceeding the dive table limits) was intentionally preserved rather than replaced with modern error catching.

## 6. Archival Record and Document Context
The `/docs/` repository contains over 50 concurrent markdown (.md) workspace files captured throughout the 2026 forensics and transcription phases. While core files like `CoordinateSystem.md` represent the finalized, tested computational parameters of the system, individual file segments in the sub-directories remain frozen in their original historical workspace states. These unedited logs preserve the ongoing diagnostic theories, intermediate version thresholds, and technical anomalies exactly as they were encountered during the recovery process.

## 7. Agent Workspace and Workflow Terminology
Throughout these raw background logs, programmatic references are made to two distinct AI development pipelines that operated under strict human-in-the-loop oversight during the 2026 transcription:
* **HK (Housekeeping):** An evaluation and validation agent layer utilized strictly for forensic analysis, structural code auditing, table matrix cross-checking, and historical document interpretation. HK did not author source code.
* **SB (Sandbox):** An execution and translation agent layer utilized for rapid prototyping, logic compilation, and code blocks mapping the BASIC-to-JSX environment paths.

The human developer acted as the sole intermediary and absolute arbiter between these pipelines—critiquing structural outputs, challenging modern styling biases, and manually verifying system execution against primary visual evidence to achieve total historical fidelity.

Through this rigorous validation process, the final application functions as a genuine digital monument: an accurate, interactive window into a seminal 1978 moment in human-computer interface design.
